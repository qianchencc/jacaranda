# 交互式微缩场景创作

把参考中的视觉关系和体验顺序转成可检查的场景约束，再逐层实现。把用户能否看见、理解和感受到效果作为验收依据。

## 先读取任务与源工程

1. 确认用户要新建、修改场景，还是只整理经验；只整理文档时，不修改运行代码或重新发布场景。
2. 修改已有作品时，定位对应项目和当前源码，保留现有交互与资产。区分真实工程、旧版本和说明性重建，不凭网页截图重写已有工程。
3. 读取适用的仓库指引，确认运行方式、依赖、坐标约定、随机种子和可用验证环境。
4. 将视觉目标与缺陷分别记入 [场景任务模板](assets/scene-brief-template.md)。通常直接作出合理设计选择；仅在缺失信息会改变主要方向时提问。

## 1. 先拆解参考，再确定构图

- 从参考视频选择总览、侧面、俯视、细节、日夜状态及关键交互前后的帧；同时记录镜头和动作顺序。
- 分别提取形体、空间关系、光色、运动、交互和排版。不要只摘取“紫色、奶油、柔和”等风格词。
- 明确三个层次：主角是什么，什么负责衬托，哪里必须留空。
- 为入口、阳台、长椅等重要对象规定至少一个清楚可见且可操作的视角。
- 建立建筑、树干主枝、地台、相机和 UI 占位的简模。先看正面、侧面和俯视，再添加细部。
- 已有参考与用户反馈足够时，确定一个可执行方向并实现，不把每个常规选择变成确认环节。

**阶段验收：** 在没有繁密花簇和装饰的情况下，构图、建筑比例与主次关系已成立。

## 2. 从结构生成建筑与植被

- 用连续平面轮廓协调圆弧墙体、线脚、阳台和女儿墙，避免圆角构件互不一致。
- 把装饰密度集中在有意义的位置；用安静的大立面衬托精细铁艺、入口和薄雨棚。
- 为会打开的门构造真实洞口、门轴、内凹空间与光照变化。
- 按树干、主枝、次级枝、细枝、花序的顺序生成植被；让花簇沿细枝形成有空隙的花冠。
- 分别设计各树的姿态、重心、分枝角度和轮廓，再加入受约束的随机变化。
- 先调整枝条和花序分布来解决遮挡；谨慎使用建筑避让范围，不把花冠切出突兀平面。

**阶段验收：** 树能看出连续分叉，花冠不是封闭球体；建筑与植物互相衬托，重要对象保持可读。

## 3. 用光照与材质建立氛围

- 先确定主光方向、环境填充和局部暖光的职责，再调颜色、粗糙度、曝光与雾。
- 保留暗面和局部高光，让暖灯照到附近树干、花瓣和铺地；不要把所有物体整体染黄或抬亮。
- 用受控的形体、柔和阴影和材质层次实现三渲二观感，不把过量发光当作氛围。
- 连续插值昼夜相关状态，并从当前状态开始被打断后的新过渡，避免跳光。
- 在白天和夜晚都检查紫色花冠、奶油建筑与地面之间的明度分离。

## 4. 把风动、脱落和落定连成因果关系

仅在任务需要风、落花或落叶时执行本节。

- 用同一时钟和连续风场驱动树干、枝条、附着花簇与脱落物；固定根部，区分主干与枝梢的响应。
- 让 GPU 变形、CPU 出生点采样、法线及阴影路径使用一致的坐标和公式。
- 从实际移动的花簇释放花瓣，继承部分枝条运动；用共享风速与阻力产生运输，再叠加较弱的个体翻转。
- 让花瓣接触路径上的第一处有效表面，覆盖屋顶、檐口、雨棚、阳台和地面；墙面接触去除向内速度。
- 按旋转后几何的最低支撑点计算接触高度；转平、压低并转入积落网格时保持位置与显示尺寸连续。
- 分别设计已有积落与持续新落定：在树冠下方和背风处形成松散片区，保留空面与入口动线。
- 最后才调整数量、尺寸、对比和释放频率，并用实际投影检查“是否看得见”。

**不要沿用：** 空中凭空生成前景花瓣、隐形反射走廊、只换颜色不动枝条、到地面前缩没、满屋面均匀撒点。

## 5. 让交互与场景对象相互解释

- 将长椅、门、书刊或阳台的交互结果与对象本身联系起来，而不是都弹同一种信息卡。
- 同时设计交互前、进行中、完成、取消和返回状态。
- 区分点击、拖动、多点触控和右键；处理建筑遮挡，避免从背面点到前门。
- 让镜头、日夜、门扇与延迟打开的面板能被中断、反向和取消。
- 共同设计页面和相机：为侧栏、标题、底部控件与弹层预留画面；手机上同时核对相机距离和控制器限制。
- 保持暂停、减少动态效果、键盘和焦点行为一致。图形不可用时明确提示，并保留可独立使用的内容。

## 6. 逐层验证后交付

1. 验证结构：源文件、模块接口、坐标、随机性、状态转换和资源路径。
2. 验证几何：真实树形、建筑比例、遮挡、承接高度、接触姿态与积落分布。
3. 验证交互：旋转缩放、点击与拖动、日夜中断、开关门、弹层返回和手机布局。
4. 验证实时表现：在可运行 WebGL 的浏览器检查着色器、实际画面、连续运动与帧率。
5. 对同一机位、相同种子和明确时间点进行前后对照；为最终证据记录对应源码版本。
6. 根据观察到的缺陷作针对性修正。达到当前任务的验收标准后，停止无目的的增饰和重复测试。

将浏览器截图、离线几何渲染、CPU 模拟和源码检查分别标明。缺少某一层证据时，说明尚未验证的部分，不能用“测试通过”概括全部效果。

交付可运行工程或用户指定的平台结果，并说明本次改变、实际检查及剩余限制。使用目标平台的现行工具与流程，不在此 skill 内固化账号、项目身份、发布凭据或权限操作。
