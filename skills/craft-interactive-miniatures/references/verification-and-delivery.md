# 验证与交付

## 1. 先声明证据层级

| 证据 | 可以支持的结论 | 不能单独支持的结论 |
| --- | --- | --- |
| 源码和模块检查 | 接口、空间约定、状态路径、资源完整性 | 视觉质量、GPU 编译和帧率 |
| CPU 模拟与真实 THREE 几何 | 出生点、运动数值、接触、投影和射线关系 | 完整像素可见性与浏览器表现 |
| 模拟 DOM/renderer 的交互检查 | 已覆盖的事件与状态转换 | 实际触控体验、浏览器渲染性能 |
| 从生产模型导出的离线图 | 树形、比例、遮挡、几何落点、两个时刻的位置差异 | 与在线渲染完全相同的光色、连续流畅度 |
| 实际浏览器截图或录屏 | 已观察到的页面、渲染、操作与运动 | 未覆盖设备、状态和长时间运行 |

只陈述对应证据能支持的结论。浏览器图形不可用时，继续可完成的结构、交互状态和离线几何检查，并明确剩余缺口。

## 2. 从真实工程运行

确认依赖和构建方式。对 buildless ES modules 工程使用静态 HTTP 服务，不通过 file URL 判断其可运行性。遵循当前环境提供的预览与浏览器工具流程。

检查资源请求、运行时错误、着色器错误和图形初始化。遇到基础设施限制时记录原因；不得把渲染失败悄悄替换成静态图片后宣布完成 3D 验收。

## 3. 按风险选择镜位和状态

| 视角或状态 | 主要检查 |
| --- | --- |
| 默认总览 | 主次、建筑比例、整体树形、标题和控制区占位 |
| 屋顶俯视 | 女儿墙与烟囱、积落密度、真实承接、屋面留白 |
| 入口与长椅近景 | 遮挡、门洞、物件可读性、粒子尺寸和点击目标 |
| 阳台与雨棚近景 | 铁艺密度、棚面坡度、檐口重叠、接触穿模 |
| 侧面和背面 | 树形重复、墙后误选、后侧穿模与根部接地 |
| 白天、黄昏、夜晚及中间值 | 明度分离、局部暖光、曝光、阴影和过渡连续性 |
| 手机、短屏与横竖切换 | 可用画幅、相机距离限制、控件与热点遮挡 |

对于风动，固定机位和源码，观察一段完整阵风及平静时段。两帧可以定位位移与连接问题，流畅度必须看连续运行。

## 4. 检查具体不变量

根据本次修改选择必要检查，不为文档或低风险变更反复运行整套渲染。

- 树根保持固定，枝条和附着花簇在同一空间中连续变形。
- 脱落源与实际花簇位置吻合，所有位置和速度有限。
- 花瓣到达路径上的第一处承接面，接触后不保留在实体内部。
- 承接采样与独立网格射线一致；检查最难的圆角、檐口和女儿墙边缘。
- 积落几何得到支撑，姿态与尺寸交接连续，缓冲容量受限。
- 暂停冻结共同风动时钟；光照切换仍可工作。
- 点击、拖拽、多指和右键行为不同；背墙遮挡能阻止前门误选。
- 镜头、日夜、门扇与延迟弹层能中断、反向和取消。
- 关闭面板恢复焦点与控制；离开后台和返回后状态合理。

可对有明确生命周期的系统使用固定种子与足够长的模拟窗口。窗口应覆盖释放、飞行、落定、回收等阶段，而非照搬某个项目的测试时长。

## 5. 做可追溯的视觉修正

为每个发现记录：症状、截图/状态、可能原因、改动范围、再次检查的结果。

优先修复会改变整体观感的缺陷：错误机位、主次混乱、球状树冠、遮挡、错误受光或没有因果关系的运动。之后再微调花量、尺寸和色差。

保存相同机位、视口、时间和随机状态的前后对照。改变密度、种子或模型之后，重新确认旧证据是否还描述当前代码。

## 6. 记录最终证据

最少记录源码版本或哈希、运行入口、视口、机位、光照状态、模拟时刻、随机性来源、检查方法、发现与限制。

若使用离线渲染，记录从生产几何和实例矩阵导出的方式、CPU 对应风形变、渲染器及光照近似；不要用重新建造的“理想版本”替代实际代码。

保留失败版本资料时标明已被替代，防止后续使用者把旧轨迹、旧参数或旧截图误认为当前结果。

## 7. 交付与知识沉淀

根据用户要求交付平台 URL 或完整工程，保留静态资源与第三方许可。修改已有项目时确认项目身份和当前源码，避免同步到相似名称的另一作品。

发布使用当前平台工具与权限流程；源码同步使用目标仓库最新状态，限定改动范围，避免覆盖他人的新提交。只整理 skill 时不改变场景代码、托管配置或站点共享范围。

在最终说明中分别写清改变了什么、依据什么检查、还有什么未验证。将经验整理为可执行步骤、失效假设和检查方式，不只记录“看起来更好”或实现完成的时间线。
